# Goal integration handoff — Treasury v0.2.0

Current Goal source reviewed at https://github.com/paonxeth/proofee/tree/efa87f13478ffbf85fc607430197b146e71b3071 . Existing Goal was NOT edited. Its SDK/lock resolve5.30.1; source review details GOAL_REVIEW.md. No prepare/bind/settlement/reward APIs currently exist. New Mock is a separate TEST contract, never substitute for economic truth in production. Treasury is fresh deployment, no v0.1 migration.

## Required new Goal state/APIs (proposed Goal names; Treasury names are implemented)

1. Pin treasury AccountId + interface version proofee-treasury/0.2.0. Admin registers trusted Goal externally in Treasury. Guard against creator/verifier self-judging. Existing no-key/no-upgrade Goal cannot be retrofitted; deploy approved new Goal version. Preserve existing P0.
2. prepare_challenge: sync fees first (must NOT be skipped by payout_in_flight); fix milestone/proof attempt/hash, challenger original payer, F snapshot, B,R,case/submission IDs and explicit immutable deadlines. One active official challenge per proof; Treasury currently permanently enforces one per proof attempt and case. Proof ID must include attempt identity, not just milestone index.
3. Call register_intent({intent}) with ZERO deposit from Goal. Goal identity is predecessor, not supplied goal string. Store RegisterPending before promise. Private callback decodes returned escrow_id and verifies version/expected metadata. On failure RegisterRetryable; identical request idempotently returns same escrow. No backend tx hash as evidence.
4. Challenger calls Treasury deposit_bond(escrow_id), exactly B, from original payer. This does NOT register eligible Challenge in Goal yet.
5. bind_bond/confirm_escrow: Goal reads Treasury get_bond on-chain, verifies goal,proof,case,submission,payer,amount,deadlines,Deposited/Bound. Then Goal calls bind_bond. Store VerifyPending/BindPending; private callback checks promise result and attempt, then mark Bound/eligible. Failed/lost callback requires view reconciliation, never assume failure implies no binding. Until bound official Challenge does not proceed.
6. Qualification on-chain: Rejected -> authorize_decision(QualificationRejected), then AFTER successful callback settle_bond(REFUND). Qualified -> explicit Goal Qualified state; Verifier can now arbitrate. Treasury trusts owning Goal's decision, not off-chain data.
7. Arbitration: substantive ProofValid -> authorize_decision(ProofValid), then settle_bond(SLASH). Substantiated challenge with final forfeiture -> authorize_decision(ProofInvalidFinal), then settle_bond(REFUND). Persist immutable decision and unique bond:<case> settlement ID before calls. authorize callback success is required before settlement. Retry same intent/decision/settlement; conflicts rejected. Accepted settlement is NOT confirmation of wallet receipt; query Treasury until Refunded/Slashed, handle RefundPending and RefundRetryable.
8. Timeout: no call to authorize_decision is necessary. Anyone may call Treasury refund_expired using stored ns deadline. Orphan timeout prevents late bind; active Bound arbitration timeout neutral REFUND, never slash/reward. Goal resolve_timeout must synchronize cancellation and Treasury timeout, not treat creator Accepted as Challenge loss. Millisecond Goal clocks -> nanosecond Treasury with checked multiplication. Decide actual deadline durations with team before public bonds; Mock's demo values are not approved product policy. No extension API. A timely immutable settlement wins; absent settlement at boundary, timeout wins. Late verifier decisions/settlements fail.
9. Winning reward: reserve ONLY same Goal's actually free FINAL forfeited NEAR (not future-fee accrual, storage, creator claims, another case's reservation). Current Goal's forfeited is a computed aggregate, not an allocated spendable ledger. Add per-case reward_reserved, funding_in_flight, funding_committed/spent and pending refund bookkeeping. F for disputed milestone must be defined against immediate/locked fee split; existing symbol forfeited F is NOT the new fee snapshot F. Do not silently map Rejected to Failed: existing resolve(false)->Rejected, expire(Pending)->Failed; define final-failure eligibility in approved SPEC.
10. fund_reward({escrow_id,funding_id}) attaches actual positive NEAR<=R from Goal. Treasury fixes beneficiary to escrow payer and supports one funding per escrow (partial allowed, no topups). Persist FundingPending before sending. Callback success decodes returned HASH; label and hash differ. Failed receipt restores Goal reservation; returned refund receipt may arrive before/after callback. A lost callback must reconcile get_case_funding/get_reward; NEVER blindly fund twice. Treasury payable replay fails so the extra attachment returns, but Goal must not treat this refund as income.
11. Pay only after Treasury confirms principal Refunded. Goal calls pay_reward(funding_hash,reward:<case>); persist PayPending/Accepted separately from Paid. Anyone may retry_failed_reward only after Treasury PayRetryable; immutable same beneficiary/amount. Same settlement replay won't retry a failed transfer; use retry method. Query Paid before showing paid in UI.

## sync/claim changes required before production Goal integration

Current Goal only tracks one creator payout_in_flight and last_balance. Extend accounting to every reward funding transfer and refund order. Either serialize outgoing operations with a unified in-flight state and block/defer sync/claim, or prove a multi-transfer accounting model with per-attempt counters. Lower expected balance for committed funding; restore on failed funding without re-counting returned NEAR as creator fees. On lost callback reconcile authoritative Treasury first; do not release reserved money speculatively. Creator claim must never spend reserved reward or storage. Test both refund-before-callback and callback-before-refund, fees arriving during success/failure, concurrent cases, and exact conservation. Existing creator-claim protections cannot simply be copied without accounting for reward funds already transferred.

## Mock Goal reference

contracts/mock_goal implements this PUBLIC Treasury ABI. Admin controls simulated fee snapshots and Qualification, verifier controls arbitration; only Qualified can arbitrate; verifier!=payer; only payer/admin can bind or request reward claim; callbacks private with stage+attempt guards. Treasury and Mock no-key deploy prevents code/key bypass. Mock fund_mock/fund_case uses admin-endowed TEST NEAR to simulate a reserve; it does NOT establish real milestone forfeiture or production Goal fee accounting.

Refresh views reconcile completed payout; recover_funding handles lost funding callback. Some lost callbacks can still leave Pending and need read-only investigation; never reset/resend a payout merely on elapsed time. Production recovery/migration needs separately reviewed design.
